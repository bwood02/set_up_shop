# Integrated Project Prep Plan (Web App + ML Notebook)

## Goal

Complete both semester deliverables with a single consistent pipeline:
- Part 1: deploy a working practice website backed by shop data.
- Part 2: deliver a CRISP-DM notebook predicting `orders.is_fraud`.

## Chosen Stack Defaults

- Frontend/web app: Next.js (TypeScript, App Router)
- Hosting: Vercel
- Cloud data layer: Supabase Postgres
- ML workflow: Jupyter Notebook + scikit-learn pipeline artifacts
- Security posture: server-side data access, minimal exposed keys, classroom-safe setup

## Deliverable 1: Web App on Vercel

### Required app features to implement

- Select Customer screen (no auth required).
- Customer dashboard with order summary metrics.
- Create new order flow that writes to the database.
- Order history page for selected customer.
- Late Delivery Priority Queue page (top 50 by predicted late-delivery probability).
- Run Scoring button that executes inference and refreshes the queue.
- A visible site section/page that displays pipeline prediction results generated by the scoring step.

### Build sequence

1. Inspect and map relevant `shop.db` tables for customers, orders, order lines, products, and scoring outputs.
2. Create Supabase project and migrate SQLite schema/data with parity checks.
3. Scaffold Next.js app and add database access layer through server-side route handlers/actions.
4. Build the required pages/actions in rubric order (Select Customer -> Dashboard -> History -> New Order -> Queue -> Run Scoring), then add prediction-results display in the UI.
5. Add production-safe error states and basic input validation.
6. Deploy to Vercel and run a full click-through verification against production data.

## Deliverable 2: CRISP-DM Notebook (`is_fraud`)

### Notebook sections (rubric-aligned)

- Business Understanding: fraud problem framing, success criteria, and tradeoff goals.
- Data Understanding: load from SQLite, profile target balance, and feature-level exploration.
- Data Preparation: cleaning, joins, leakage checks, engineered features, reusable prep pipeline.
- Modeling: baseline + at least one ensemble classifier.
- Evaluation: metrics, threshold reasoning, model comparison, and tuning.
- Deployment: serialize chosen model and demonstrate inference integration path.

### Minimum technical outputs

- Reproducible notebook run from top to bottom.
- Saved model artifact (for example `joblib`/`pickle`) and preprocessing pipeline.
- Clear final model selection rationale tied to business objective.

## Suggested Timeline (Class-Ready)

- Session 1: schema inspection + Supabase migration.
- Session 2: core pages (Select Customer, Dashboard, History).
- Session 3: New Order + scoring queue + Run Scoring flow.
- Session 4: deploy and production verification.
- Session 5: complete CRISP-DM notebook and export final artifacts.
